The files it names as `research/eval/{climb,climb2}-log.jsonl`, `research/eval/final*.txt`, `hill-climbing-2-*.txt` and `ACCEPTANCE-hill-climbing-1*.md` are now in `research/eval/history/`, and `docs/state-space-hill-climbing-2.md` is `docs/history/state-space-hill-climbing-2.md`. The search scripts it names were removed from the repository once their conclusions were recorded; they are at the tag `archive/pre-tidy-2026-10-14`.

Written and committed **before any candidate was run**. It restates the objective, gates and procedure of the
"Hill-climbing objective" section of `OPEN_PROBLEMS.md` in operational form (exact formulas, exact thresholds). Where the TODO
leaves a detail open, the choice made here is marked **[choice]** so it can be audited. Nothing in this file may be
changed after a candidate has been run; a change would be a new, dated amendment at the bottom.

Predictive loss always wins over structure. A structural gain that costs forecast loss is rejected.

## Data discipline

- `--holdout` (2016+) is never used. Nothing here reads 2016 or later.
- **2012-2015 is not looked at while climbing.** The climb script cuts the timeline at 2011 *before* any filter runs
  (the filters are forward-only, so 2002-2011 results are identical to those of the full run; the script checks this
  against `baseline.json`). 2002-2007 is the fit window of the calibration multiplier, 2008-2011 is the validation window.
  The script never prints or logs a number from a later year.
- **[choice] D is computed on the timeline cut at 2011, not on the full 2000-2015 run.** The movers, lineup changes and
  error-bar revisions that make up D are events spread over 2000-2015, so D from the full run would read 2012-2015.
  The formulas and constants below are unchanged; only the events are those of 2000-2011. D0 on the cut timeline is
  measured by the script (candidate 0) and recorded in `hill-climbing-1-log.jsonl`; D0 from the full baseline is recorded below.
  The goal `D <= 0.4` is judged on the cut-timeline D during the climb, and on the full-run D at the one
  confirmation that touches 2012-2015.
- 2012-2015 is touched exactly once: the confirmation run of the final settings.
- Never edited: `exam.js`, `observations.js`, the metric code in `packages/eval`. If a metric looks wrong it is
  reported, not changed. `presets/state-space-fit.js` is regenerated by `state-space-calibrate.mjs`, never edited.

## The two numbers

All losses are the harness's own ratings-alone weighted log-loss (`predictive.table` of `evaluateModel`), with each
session's calibration multiplier fitted on 2002-2007 and then frozen (the harness default).

### P (predictive; lower is better)

Let `cell(win, s)` be the harness's `all`-pairs cell for window `win` in {fit = 2002-2007, w2 = 2008-2011} and session
`s` in {race, qual}, with `loss` and `weight` (the exam's total observation weight).

```
P = sum_{win, s} loss(win, s) * weight(win, s)  /  sum_{win, s} weight(win, s)
P_w2 = the same sum over win = w2 only          (the 2008-2011 reference loss)
```

### D (structural deficit; lower is better; race session)

```
d1 = |teammates.race.leak.k5| / 0.13                           stayer leak, target 0
d2 = max(0, 0.9 - movers.race.frozenSlope.k5) / 0.55           frozen-rating slope of movers, target >= 0.9
d3 = |ln(health.race.uncertainty.driver.z2)| / ln(8.8)         error bars, target z2 = 1
d4 = max(0, movers.race.step.k1.rmsRatio - 2.0) / 0.84         mover step excess over a correct filter
D  = (d1 + d2 + d3 + d4) / 4
```

All four inputs are point estimates (`.est`) of the harness headline; the bootstrap does not affect them.

### Reference values (from `research/eval/baseline.json`, shipped settings)

| | value |
| --- | --- |
| **P0** (2002-2011 pooled) | **0.386932** |
| 2002-2007 combined, all pairs | 0.386158 |
| **P0_w2** (2008-2011 combined, all pairs) | **0.387680** |
| race / qual pooled over 2002-2011 | 0.387849 / 0.379849 |
| inputs of D | leak.k5 0.12822, frozenSlope.k5 0.34601, z2 8.8371, rmsRatio.k1 2.8430 |
| d1, d2, d3, d4 | 0.9863, 1.0073, 1.0019, 1.0036 |
| **D0** (full baseline) | **0.99977** (the TODO's "1.0") |
| forecast layer 2008-2011: race-day / Thursday / qualifying head | 0.3371 / 0.3819 / 0.3492 |

The reference for every gate is the shipped settings *as measured by the climb script on the cut timeline* (candidate
0). Candidate 0 must reproduce the 2002-2011 numbers above to 1e-6; if it does not, the climb stops.

## Hard gates (a step is rejected if any fails)

Evaluated on 2002-2011 (windows fit and w2). `ref` is candidate 0.

| Gate | Rule |
| --- | --- |
| G1 ratings-alone, combined, all pairs | each of fit and w2: loss <= ref + 0.0005 |
| G2 forecast layer, 2008-2011 | race-day <= ref + 0.001; Thursday <= ref + 0.001; qualifying head <= ref + 1e-6 |
| G3 window x session x pair type | every cell of {fit, w2} x {race, qual, combined} x {all, mates, cars}: loss <= ref + 0.002 |
| G4 calibration slope out of the fit window | race and qual, all pairs, on w2: within [0.95, 1.05] |
| G5 walk-forward (multiplier refitted yearly) | race and qual on w2: loss <= ref + 0.0005 |
| G6 qualifying structure, **[choice]** | `dq1 = abs(teammates.qual.leak.k5)/0.13`, `dq2 = max(0, 0.9 - movers.qual.frozenSlope.k5)/0.55`, `dq3 = abs(ln health.qual.uncertainty.driver.z2)/ln 8.8`: each <= ref + 0.15 |
| G7 car shocks (race), **[choice]** | `abs(shocks.race.leakFree.X) <= abs(ref) + 0.03` for X in winterUnchanged, winterJoined, season |
| G8 rookie bias, **[choice]** | `abs(rookies.S.bias.first5) <= abs(ref) + 0.02` for S in race, qual |

The 2012-2015 half of the TODO's rule ("no window ... worse") is checked once, at the confirmation.
G2 is measured with the shipped heads (trained on the shipped ratings) and with the session multipliers refitted on
2002-2007 for the candidate, in process, exactly as `state-space-calibrate.mjs --write` would write them: **[choice]** the
heads are not retrained inside the loop (a Python/scikit-learn fit per candidate is out of scale), so G2 is a
stale-heads test and is, if anything, biased against a candidate whose rating geometry moved. G2 is evaluated
lazily, only for a candidate that passes every other gate and would otherwise be accepted.

## Acceptance of a step

Keep `P_best` = the lowest P among accepted points so far (starts at P0) and the current point `(P_cur, D_cur)` = the
last accepted point (starts at `(P0, D_ref)`, `D_ref` = D of candidate 0). **[choice]** Comparing with the best P ever
accepted, not with the current point, prevents a chain of "P within 0.0003" steps from drifting P upwards.

Accept a candidate if every gate holds and one of:

1. `P <= P_best - 0.0003` and `D <= 1.10 * D_cur` (P improves by at least 0.0003; D not worse by more than 10%), or
2. `|P - P_best| < 0.0003` and `D <= 0.90 * D_cur` (P tied; D better by at least 10% relative).

Goal: `D <= 0.4` with `P <= P0`. A predictive win is `P <= P0 - 0.001`. If `D <= 0.4` cannot be reached without costing
predictive loss, stop at the best P and report the trade-off curve (every candidate's (P, D) is in the log).

Differences inside the noise (about 0.0005 in the ratings-alone exam; about 70 movers and 45 lineup changes in D) are
not chased: no step is accepted on a tie, and the confirmation run reports intervals.

## Procedure

- Candidate = the shipped settings plus a dict of overrides for one session (race or qual) at a time.
- Cheap run: the script's equivalent of `--null 0 --boot 50` on the cut timeline. Deterministic (the filters and the
  seeded season bootstrap have no free randomness).
- Coordinate search with multiplicative steps, one setting at a time, race and qualifying separately, steps as in
  `state-space-fit.mjs` (x/÷1.4 for `tau`, `thetaT`; x/÷1.5 for `mPace`, `mPart`, `sdJ`, `sdA`; x/÷1.3 for `sdNew`, `winterC`,
  `raceC`, `yearD`; +/-0.05 for `rhoA`). A setting at 0 is tried at one starting value (5). When a step is accepted in a
  direction the same setting is pushed further in that direction until it is rejected (at most 6 tries).
- Phase 1: `tau`, `thetaT`, `mPace`, `mPart` (qualifying has no pace or retirement pairs, so `mPace`, `mPart` are
  skipped there). Phase 2: `sdJ`, `sdA`, `rhoA`, `sdNew`, `winterC`, `raceC`, `yearD`. A phase stops after 3
  consecutive rounds (a round = every setting of the phase, both directions) with no accepted step, or after 60
  candidate evaluations.
- Every candidate is appended to `research/eval/hill-climbing-1-log.jsonl`: its overrides, P, the loss by window x session x
  pair type, D and d1-d4 with their inputs, the guards, the forecast layer if it was computed, the gate results and
  the verdict. The weak slices (movers' frozen and online duel loss, rookie bias and slope, wet versus dry, the
  `partial` source, variance terciles, link classes) are logged for every candidate and reported in the write-up.
- If `D > 0.4` after the climb: (a) a covariance inflation used only for the reported uncertainty, (b) a lineup-change
  specific car variance, and only then (c) a learned gain, which is a last resort and only after Simulator v2 passes its
  realism checks. Each is judged by the same gates and the same acceptance rule.
- Synthetic recovery (truth-based leak, error against the true levels, truth inside the bars) is checked on the
  accepted points with the synthetic worlds, so that a gain is not the car or the driver absorbing the split.
- Final: one full run on the final settings (`--model both --full --null 4 --boot 300`), which touches 2012-2015
  exactly once, and a write-up of the baseline and final scorecards side by side, predictive table first, with a
  plain statement of whether the result improves forecasts, only structure, or neither. Negative results are reported.

## Amendments

### Amendment 1 (2026-10-07, after candidate 0, before the first candidate)

Candidate 0 (`climb.mjs reference`) reproduces `baseline.json` for every 2002-2011 cell and for the 2008-2011 forecast
layer to 1e-6. Reading it showed two things the rule above did not anticipate. No candidate had been run.

1. **G4 as written fails for the shipped settings.** The baseline's qualifying calibration slope is 1.009 over
   2008-2015, but on 2008-2011 alone (the only out-of-fit window the climb may read) it is **1.059**, outside
   [0.95, 1.05]. A gate the reference cannot pass would reject everything. G4 is replaced by: race and qual, all pairs,
   on w2, `|slope - 1| <= max(0.05, |ref slope - 1| + 0.02)`. The reference slopes are race 0.9951, qual 1.0594, so the
   limits are race [0.95, 1.05] and qual [0.921, 1.079]. The 0.95-1.05 band is still applied to both sessions at the
   confirmation, on 2008-2015.
2. **D0 on the cut timeline is 0.853, not 1.0** (inputs: leak.k5 0.1004, frozenSlope.k5 0.4599, z2 8.122,
   rmsRatio.k1 2.737; d1-d4 = 0.772, 0.800, 0.960, 0.881). The events of 2000-2011 are a subset of those of
   2000-2015. The acceptance rule is relative to the current point, so it is unaffected. The goal stays `D <= 0.4`
   on the full-run D at the confirmation (a 60% cut from 0.99977); during the climb the cut-timeline D is reported
   next to the same 0.4 line and next to `0.4 * D0_cut = 0.341`, the equivalent relative reduction.

No other rule changes. P0, P0_w2 and every other reference value above are unchanged.

### Amendment 2 (2026-10-07, after candidates 1-55: written knowing which candidates it affects)

The coordinate search (candidates 1-42) accepted nothing. Four candidates passed every gate but G2 and would have been
accepted on P and D: #2 `tau` 0.05 -> 0.0357 (P -0.00036, D 0.853 -> 0.792), #6 `mPace` 25.6 -> 17.1 (P -0.00041,
D -3.6%), #43 `tau` 0.0255 and #44 `tau` 0.0182 (scan), all failing only "qualifying head +0.0001 to +0.0005". The
cause is the staleness the rule itself flagged: the shipped heads were fitted on the shipped race ratings, and the
qualifying head reads race ratings as inputs.

Refitting the heads for a candidate turned out to be cheap (about 30 s: `climb-heads.mjs` exports the rows through 2011, and
`refit-heads-w2.py` fits the frozen head designs on rows through 2007 and scores 2008-2011), and on the shipped
settings it reproduces the shipped forecast layer to 1e-8 (race-day 0.337146, Thursday 0.381945, qualifying head
0.349179). So **G2 is now evaluated with heads refitted on the candidate's ratings** (still walk-forward: fitted through 2007, scored
2008-2011), against the same refit on the shipped settings, with unchanged tolerances (race-day and Thursday <= ref +
0.001; qualifying head <= ref + 1e-6, i.e. no worse). The stale-heads figures stay in the log for candidates 1-55 (field
`fc`, no `fh`); entries from now on carry the refit figures (`fh: "refit"`).

### Amendment 3 (2026-10-07): the reported-uncertainty inflation `varInfl`

Step 2 of the TODO's structural list was implemented as `varInfl` (a multiplier on the variance the filter reports; the means
and every forecast are unchanged; `varInflPred` separately scales the variance a forecast folds into its probability and was
found not to help: P +0.0001 at x2, +0.0010 at x7.9). `varInfl = 7.88` is the driver z2 of the 6-race revision test fitted on
2002-2007 only (7.8806 on the fit window), so it is a calibration constant of the same kind as the multiplier. It was accepted
as candidate #55 (rule 2: P identical, D 0.853 -> 0.616; driver coverage of the 90% bar 0.38 -> 0.89).

Once `varInfl` is in the current point, every candidate that changes another race setting re-fits it on 2002-2007 (setting
`varInfl: "auto"` in the script), because the z2 scales with `tau` and the other settings: leaving it fixed would make d3
penalise or reward every step for a calibration the step did not choose. This re-fit uses only 2002-2007.

### Amendment 4 (2026-10-07): compound steps, an extension of the procedure (not part of the TODO's)

The TODO's procedure moves one setting at a time. With the acceptance margins (P better by 0.0003, or D better by 10% when P
is tied) many single steps are individually too small to count: in the first pass, `winterC` -23% gave P -0.00027, `sdNew`
-23% P -0.00019, `sdJ` and `sdA` -33% each gave D -4% to -6% for P +0.0001, and so on. After a phase has stopped, the
script (`search --compound`) therefore combines the single steps that were judged against the current point, cost less than
the acceptance margin in P and lowered D, ranks them by `D/D_cur + max(0, dP)/0.001`, and judges the combination of all of them,
then of each smaller prefix, as ordinary candidates: same gates, same rule, logged with phase `4`. Compound steps are labelled as an
extension in the write-up; the specified coordinate search is reported on its own.

### Amendment 5 (2026-10-07): one more candidate setting, `tauWet`

The TODO asks to check the wet and retirement slices for gains (wet calibration slope 0.80, partial pairs 0.5). A wet weekend reshuffles the
order more, so it should teach the ratings less. `tauWet` multiplies the likelihood weight of a wet weekend's pairs (wet flags are the
calendar's, known at the update, no look-ahead; 1 = off, the shipped behaviour). It is tried as an ordinary candidate (race only; qualifying
has no wet slice in the exam) from the current point, with the same gates and the same rule, logged with phase `5`; values 0.3-1.4 are scanned.

### Amendment 6 (2026-10-07, before 2012-2015 is touched): the confirmation protocol

The climb is over: the current point of the log is the final point (no further candidate is judged after the confirmation). The one look at
2012-2015 is a single sequence: apply the final settings to `presets/state-space.js`; regenerate `presets/state-space-fit.js` with
`state-space-calibrate.mjs --write`; refit the forecast heads on the final ratings (`export-state-space-rows.mjs --through 2015`, then
`finalize-state-space.py --ship`), which the forecast layer needs to be consistent with the ratings it reads; run the harness once
(`--model both --full --null 4 --boot 300`); and compare with `research/eval/baseline.json`. The settings are kept as the shipped defaults only if
all of the following hold; otherwise the preset change is reverted and the result is reported as a negative one (the code, the log and the
write-up stay):

1. **Ratings alone**, combined, all pairs: not worse than baseline by more than 0.0005 in any window (2002-2007, 2008-2011, 2012-2015) and pooled 2008-2015.
2. **Forecast layer** (refit heads against the shipped heads), 2008-2011 and 2012-2015: race-day and Thursday not worse by more than 0.001;
   qualifying head not worse by more than 0.0005 (the exam's noise floor: a 1e-6 tolerance is a coin flip on a window nothing was selected on).
3. **No window, session or pair type** (teammates, other cars) worse by more than 0.002, 2012-2015 included.
4. **Calibration slopes** (all pairs, race and qualifying, 2008-2015) within 0.95-1.05; **walk-forward** loss by session and window not worse by more than 0.0005.
5. **Structure not regressed**: qualifying (G6 terms), car-shock leaks (G7) and rookie bias (G8) as in the climb, on the full run.
6. **Recovery on synthetic worlds** drawn from the BASELINE dynamics: the truth-based leak (winter unchanged, winter joined, in-season) not worse
   than baseline by more than 0.03, and the recovery error of drivers and cars not worse than baseline by more than 5%.

Reported whatever happens: the full-run D (goal 0.4) with its four inputs and intervals, the predictive table by window, session and pair type, the
weak slices, the S and T nulls, the same recovery on v2 worlds (informational: v2 is not used to judge, see docs/evaluation.md), and
the climb's cut-timeline D next to it. The full harness JSON is not committed (it is larger than the baseline file); the text report and a
small headline file are.

### Amendment 7 (2026-10-07): what the confirmation showed, and one mistake in it

**The mistake.** The first confirmation run was not of the climb's final point. A transcription slip left `sdNew` (20) and `winterC` (11.379) at
their pre-climb values in the preset (the replacement of those two lines silently matched nothing; the diff was read as if it had), so the run
was of `tau` 0.0255, `sdA` 3.33 and `varInfl` 4.953 only. That run passed every criterion (2012-2015 ratings alone +0.00035; reports kept in
`research/eval/variant-first-confirmation*.txt`; log line `CONFIRM-A`). It is **not** the point the climb selected, and choosing it now would be
choosing on 2012-2015, so it was not used for any decision. The preset was corrected to the logged final point and the sequence run again:
2012-2015 has therefore been read twice for the intended model's pipeline (once with a variant), not once. Which of the two to ship was fixed
before the second run: the climb's final point, judged by the criteria of Amendment 6, whichever way it came out. The climb script now applies every
candidate to the pre-climb values (`PRE_CLIMB`), so it reproduces after the presets changed (the final point reads P 0.386654, D 0.4055 again).

**The result for the final point** (`research/eval/final.txt`, `final-vs-baseline.txt`): ratings alone, combined, all pairs: 2002-2007 -0.0001, 2008-2011 -0.0005,
**2012-2015 +0.0009**; forecast layer 2012-2015 Thursday **+0.0010** and qualifying head **+0.0006**; walk-forward race 2012-2015 **+0.0010**; the truth-based
in-season leak on baseline-dynamics synthetic worlds +0.035. Criteria 1, 2, 4 and 6 fail (3 and 5 hold). Per the protocol the settings
(`tau`, `winterC`, `sdNew`, `sdA`) are **not shipped**: the presets, the fit file and the forecast heads are back to their pre-climb values.

**What is kept.** `varInfl` (candidate 55) is kept in the shipped presets at the value it was fitted to on the baseline settings, 7.88. It is
not covered by the confirmation of the final point, so the reason is stated here: it changes no mean, no forecast, no fitted multiplier and no
loss (the ratings-alone exam, the forecast layer and the walk-forward score are bit-for-bit the baseline's), so there is nothing for 2012-2015 to
test on the forecast side, and the TODO prefers structural fixes that are neutral on loss. Its calibration was fitted on 2002-2007 only; the confirmation's z2 of
the final point (1.13 on 2000-2015) shows the constant generalises. This keep was decided after the final point failed, and is reported as such.
